How it works

Three lines in, one run out.

The SDK records typed events, not log lines. The server stores them unchanged and derives everything else: the timeline, findings, cost. Nothing leaves your network.

  1. 01

    Wrap the agent

    A run, then a span around each tool call or command. The SDK never raises into your agent; buffers and retries are bounded.

  2. 02

    Events arrive typed

    A tool call is a tool.call.failed event with a payload, not a string to grep. Accepted events are immutable; the UI is rebuilt from them.

  3. 03

    Read the run from the top

    The headline sentence says what failed and when. The fault line marks the first error. Findings point at the events that support them.

    Failed at step 7 after 6.2 s: run_migration, ConnectionTimeout.
