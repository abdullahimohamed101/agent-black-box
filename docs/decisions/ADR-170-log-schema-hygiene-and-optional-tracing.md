# ADR-170: Log schema and hygiene, and optional tracing at the boundary

Status: Accepted (Phase 19c, step 4). Implements D4 of the Phase 19c plan; the choices below were made by the assistant under the standing instruction and are listed so they can be reversed.
Builds on INV-4 (observability never breaks the host), INV-5 (sensitive capture is opt-in, redact before export), INV-8 (OpenTelemetry is mapped at the boundary, never copied in), ADR-165/168 (metrics rules, closed vocabularies).
Date: 2026-10-16
Phase: 19c

## Context

Logs were structured JSON already, but the request line carried the raw path (so ids and query-less identifiers reached the logs: the step 1 security note), exception text could reach a line through `exc_info`, `operation` and `error_type` (spec 116.2) were missing, nothing proved the call sites could not leak, and at `LOG_LEVEL=DEBUG` SQLAlchemy and asyncpg log every statement with its parameters, which are payloads, keys and addresses. Tracing (116.3) did not exist. Separately, the installed FastAPI (0.142) ships its own OpenTelemetry: it records `url.path` and `url.query`, the original input of validation errors and exception messages and stack traces, and **auto-exports to whatever `OTEL_EXPORTER_OTLP_*` collector it finds** once the SDK and the OTLP exporter are installed, which is exactly what the `otel` extra installs.

## Decision

### Logs

1. **One schema.** Every line has `timestamp, level, service, logger, message, request_id`; plus `operation` and `error_type` where known; plus the opaque caller identifiers the authentication layer already attached (`workspace_id`, `project_id`, `actor_id`, `session_id` (8 characters of the id), never names or slugs). `operation` is a short dotted lowercase identifier set once by the code that owns the unit of work (`set_operation` / `operation()` in `core/request_context.py`: `ingest.batch`, `alerts.deliver`, `retention.tick`, `job.<type>`), and defaults for an HTTP request to `http.<endpoint function name>` read from the matched route, so no handler has to remember. Names are validated; a job type that is not a registered handler is `job.unknown`.
2. **The request line logs the route template and status, never the path.** `route` is `/v1/runs/{run_id}` or `unmatched`; `request_id` correlates a line to a client-reported id. `error_class` fields were renamed `error_type` so there is one name.
3. **Exception text never leaves the process in a log line.** `JsonFormatter` renders an exception as frames plus exception *class names* (the chain too), never messages, and sets `error_type` from the class. A database error message echoes the offending row; a library message quotes URLs. Frames stay: the stack is the evidence a crash needs, and source lines are our code.
4. **Data-bearing libraries are pinned quiet whatever the level.** `configure_logging` holds `sqlalchemy`, `asyncpg`, `asyncio` at WARNING and `urllib3`/`requests` at ERROR (httpx/httpcore already were). An operator who sets `LOG_LEVEL=DEBUG` gets our debug lines, not SQL parameters. A test proves the pins matter (unpinned, the parameter appears).
5. **The call sites are checked, not just the sink** (`tests/test_log_hygiene.py`, AST, like the timeout scan): a log call fails the test when its message is not a fixed string, it passes an exception object other than `type(e)`, asks for a traceback outside the reviewed allow-list (`exc_info`, `.exception()`), carries a value named like a body, token, secret, key, address, header, cookie, URL, e-mail, DSN, prompt or command (identifier words), reads `request.url/headers/cookies/client/query_params`, or uses an `extra` key like those. Allow-list entries carry the reason; an entry that matches nothing fails. The scan found no real data leak in the existing call sites (the code base already logged class names and fixed codes); it found one dynamic message (the session audit line) which became a fixed message with an `action` field, and the formatter and library gaps above were found by the sentinel test design. The scanner has its own tests on planted violations.
6. **The sentinel test is the INV-5 evidence** (`tests/obs/test_log_sentinel.py`): realistic and hostile traffic through the real application, worker, alert delivery, retention (dry run and enforce) and the backup/verify/restore CLIs with every logger at DEBUG, asserting no planted payload, header, cookie, key, token, address, e-mail, passphrase or DSN password in any record (message, args, extras, exception text) or in CLI output. Mutation-checked: re-adding the raw path to the request line fails it.

### Tracing

7. **Optional, off, zero cost.** Extra `otel` (`opentelemetry-api`, `-sdk`, `-exporter-otlp-proto-http`, exact pins, lockfile updated). Enabled only by `ABB_OTEL_ENABLED=1`; without the extra that is a fixed startup error (`TracingUnavailable`, no traceback detail). Everything OpenTelemetry-shaped lives in one module, `obs/tracing_otel.py`, imported by `tracing.start()` only when enabled (INV-8: the boundary maps to OTel, no OTel type is in a call site). Call sites use `with span("name", **attrs)` from `obs/tracing.py`; while off `span()` returns one shared `__slots__ = ()` no-op object. Tested by identity, an AST check that only one module imports OpenTelemetry, and a child process proving that creating the app and calling spans adds no `opentelemetry` module beyond what FastAPI imports itself (note: `opentelemetry-api` is already a transitive dependency of FastAPI 0.142, so "imports nothing" is measured as "we add nothing"; the SDK and exporter are what the extra adds).
8. **A closed attribute and name vocabulary, enforced before the SDK.** Span names: `http.request`, `ingest.persist`, `job.run`, `db.checkout`, `alerts.attempt`, `retention.tick`. Attribute keys (exported as OTel HTTP names where one exists, else `abb.*`): `method` (closed set), `route` (a route template), `status` (100..599), `job_type`, `attempt`, `outcome` (closed set), `destination_type`, `error_type` (a class name), `events`, `accepted`, `mode`. Strings are at most 64 characters and match a pattern; numbers are bounded integers. Nothing a client controls has a key: no payload, names, slugs, ids, paths, query strings, headers, SQL text or parameters. **Tenant identifiers are not attributes** (same rule as metrics labels; a trace id plus the request id correlate without them). A refused attribute is dropped and counted, never raised into a request (INV-4), except under `strict`, which the tests switch on so that every real call site is proved to set only allowed attributes.
9. **No second source of spans.** FastAPI's native telemetry is switched off at `FastAPI(telemetry=...)` (tracing, metrics, logs, operation spans and, above all, `auto_configure`), whatever the environment says; a test checks the flags and that no exporter is started. An **inbound `traceparent` header is ignored**: it is client-controlled and would let any caller force sampling (an exporter flood) or forge a trace id. Every request is a new root span; `ParentBased` still applies to child spans.
10. **Async work is linked, not parented** (spec 116.3). `OutboxRepository.enqueue` stores the current span's W3C `traceparent` (55 characters) in the job payload when tracing is on (a job that coalesces into a pending one keeps the first context); the worker validates it on read (`valid_traceparent`: version 00, exact shape, non-zero ids, never trusted beyond that) and starts `job.run` as a root span with a **span link** to it. The carried context is the span that did the enqueue (`ingest.persist`, a child of the request span), so the link lands inside the request's trace. The job span carries `job_type`, `attempt` and `outcome`; a failure sets the error status without a description and `error.type` as the class, never `record_exception` (an exception message can quote a payload value).
11. **Coarse database spans only:** `db.checkout` around `Pool.connect` (wait, connect and ping), and the commit is inside `ingest.persist` (which wraps `engine.begin()`). No statement text or parameters, no per-query spans.
12. **Sampling and export.** `ParentBased(TraceIdRatioBased(ABB_OTEL_SAMPLE_RATIO))`, default 0.1. A batch processor with a queue of 2048 (spans beyond it are dropped silently, bounded memory), exporting OTLP/HTTP with the standard `OTEL_EXPORTER_OTLP_*` variables read by the exporter itself: the endpoint and **headers (secrets) are never in `Settings`, never read or logged by our code**. The exporter is wrapped: an exception or a failed result is swallowed, logged once as `trace export failed` with the exception class, and counted in `otel_export_failures_total`. The `opentelemetry` loggers are silenced because the exporter's own failure lines quote the collector URL and response text. Shutdown (`ABB_OTEL_SHUTDOWN_TIMEOUT_SECONDS`, default 5) flushes and closes on a daemon thread and is abandoned at the budget: the SDK's flush runs the exporter in the caller with no deadline, so a collector that never answers would otherwise hold a stop.

## Alternatives considered

- **Keep logging `exc_info` and rely on review.** Rejected: one reviewed line is not a guarantee; the sink now makes it structurally safe and the scan keeps call sites honest.
- **Honour inbound `traceparent`** (the usual instrumentation default). Rejected for an internet-facing ingestion API (item 9); SDK-to-server trace stitching can come later behind an authenticated, key-bound opt-in.
- **Adopt FastAPI's native telemetry instead of our spans.** Rejected: it records raw paths, queries, validation inputs and exception messages and cannot be allow-listed; our boundary must be the only one.
- **A tenant or project id attribute** for per-tenant trace search. Rejected by default for the reasons of ADR-165; revisit if operators ask, as a closed opt-in.
- **`opentelemetry-instrument` auto-instrumentation.** Rejected for the same reason as FastAPI's: attributes are not ours to bound.

## Dependencies (the five questions)

The extra adds `opentelemetry-sdk`, `opentelemetry-exporter-otlp-proto-http` (and, transitively, `opentelemetry-proto`, `-semantic-conventions` and the exporter's common/transport packages, `protobuf`, `googleapis-common-protos`, `requests`, `urllib3`, `charset-normalizer`: twelve packages in the lockfile, none installed by default); `opentelemetry-api` is already present through FastAPI. 1. *Needed?* Tracing across async boundaries is spec 116.3; writing an OTLP exporter by hand would be worse. 2. *Standard library or existing dependency instead?* No: OTLP/protobuf and the sampler/propagator semantics are the standard. 3. *Maintained and licensed?* CNCF project, Apache-2.0, released together. 4. *Blast radius?* None in the default install: not installed, not imported, not in the default image (`--build-arg UV_SYNC_ARGS="--extra otel"` adds it); in a tracing install the exporter runs on its own thread and cannot raise into a request. 5. *Pinned and audited?* Exact pins, in the lockfile, covered by the lockfile audits of step 7.

## Consequences

- A quality job that installs the extra runs `tests/obs/test_tracing_otel.py`; without the extra that module skips with its reason and `test_tracing_off.py` still proves the off path. The CI workflow change is owned by the CI step (KI to file).
- `mypy` is clean with and without the extra (an override for the optional names; no per-line ignores).
- Metric `otel_export_failures_total` is in the catalogue and the OPERATIONS table. It reaches `/metrics` of the API and worker; the standalone retention process records it in its own registry only (not in its textfile).
- Open: an inbound-trace opt-in for SDK stitching, trace-id exemplars on histograms, and a collector alert rule (KI to file).
