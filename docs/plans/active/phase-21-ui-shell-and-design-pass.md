## Outcome

The web UI becomes an application: a persistent left rail, a slim top bar, full-width content, a run page whose header is an instrument panel (title, status, id line, one-sentence headline with an inline "Show it", one readout strip) over a work area that fills the viewport (context column, timeline/waterfall/evidence pane, right inspector). One status grammar, one superfamily of fonts, 4 px radii, structural hairlines, almost no motion. Every role, test id, keyboard shortcut, virtualized list, SSE path and viewer-withheld state keeps working; **no existing Playwright spec file or vitest file changes**; `scripts/quality.sh full` is green after every commit.

## Non-goals

- New product surfaces beyond the Evidence view (KI-108 evaluator/experiment admin screens stay deferred; KI-109 virtualised compare list stays deferred).
- A light/dark toggle, a collapsible icon rail, a command palette (⌘K), inspector tabs, a designed brand mark. Listed under "Follow-ups".
- Touching `Timeline.tsx` / `Waterfall.tsx` internals (row heights, roles, virtualizer, keyboard handling), `lib/*`, `server/*`, `fixtures/*` beyond what a step names.
- Any new runtime dependency (the five questions in `docs/BUILD_PROMPT.md` §4 are answered "the platform provides it" for fonts: `next/font/local`).

## Decisions (D1-D16; confirm before implementation)

Each is the simplest option that keeps the locked suites green; the review file records the alternatives.

- **D1 View switch stays a radio group, styled as tabs; Evidence is the third view.** `multiagent.spec.ts` (3 call sites), `fixtures.spec.ts` (6) and `run-view.test.tsx` (3) use `getByRole("radio", { name: "Waterfall" | "Timeline" }).check()`. A `role="tablist"` would require editing locked specs. The segmented control keeps native radios (`appearance: none`, filling the label, opacity 0, so Playwright still finds and checks them) with the checked label drawn as the active tab. `?view=` gains `evidence`; `RunView` becomes `"timeline" | "waterfall" | "evidence"`; the pane h2 `#tl-h` keeps saying "Timeline" / "Waterfall" / "Evidence" (`run-view.test.tsx` asserts the headings).
- **D2 Story, Agents, Findings and Evaluations stay mounted and visible on first load, in a left context column, not in tabs.** `findings.spec.ts`, `eval.spec.ts`, `coding.spec.ts`, `multiagent.spec.ts` and `fixtures.spec.ts` all read `story`, `agent-tree`, `findings`, `evaluations` and the timeline (`progress` "events shown", `option[selected]`) in the same test without any tab click. The column (`aside.context[aria-label="Run context"]`, 18rem, scrolls on its own) holds the four existing sections unchanged in DOM order Story, Agents, Findings, Evaluations. Below `100rem` viewport width, opening the inspector collapses the column to a 2.25rem strip with one vertical "Context" button (CSS state on `.work[data-inspector="open"]`; a tri-state `data-context="auto|open|closed"` set by the strip button and a header toggle overrides it). No spec asserts the context after a dialog is open (checked line by line in the review).
- **D3 The readout strip keeps the class names `.stats` / `.stat`.** `analytics.spec.ts` (locked analytics-e2e) locates dashboard figures with `.locator(".stat")`. The direction's `.readouts` / `.ro` names are not used; the rules are rewritten in place.
- **D4 `data-testid="first-error"` wraps the first-error sentence plus the inline "Show it" control inside the headline.** `fixtures.spec.ts`, `coding.spec.ts` (`toContainText("exit 1")`) and `run-detail.test.tsx` (`toHaveTextContent("run_migration")`) read the error text through that test id; `getByRole("button", { name: "Show it" })` is used by 3 specs and 2 vitest files. `headline()` keeps its signature and output (4 direct assertions); the component renders `headline(r, null, null)`'s sentence plus `<span data-testid="first-error">First error at +6.2s: run_migration · ConnectionTimeout. <button>Show it <kbd aria-hidden>e</kbd></button></span>`; for SUCCESS with a recovered error the "It recovered from an error." clause is rendered before the span. The banner `div.banner.banner-bad` is deleted.
- **D5 Fonts through `next/font/local`** (part of Next 16: self-hosting, `@font-face`, preload and fallback metrics with zero new dependencies), files under `apps/web/src/fonts/` with `OFL.txt`, exposed as CSS variables `--sans`, `--cond`, `--mono`. Seven static latin woff2 files: Plex Sans 400/500/600, Plex Sans Condensed 500/600, Plex Mono 400/500 (about 150 KB total). `display: "swap"`, `preload: true` only for Sans 400, Condensed 600 and Mono 400. Recorded as ADR-110. **Downloading the files from github.com/IBM/plex needs the user's approval first** (file download rule); the implementing agent asks before step 1.
- **D6 No search slot in the top bar.** `SearchBox` keeps living on the runs page (its state is the page's URL filters; `search.spec.ts` and `fixtures.spec.ts` drive it there). The top bar is crumbs + `LiveIndicator`; no placeholder "⌘K" affordance that does nothing.
- **D7 Rail navigation = Overview, Runs, Analytics, Experiments, Settings (session mode only).** `SettingsNav` (`nav.subnav[aria-label="Settings"]`, permission-filtered) stays exactly as it is on settings pages, restyled as a tab row. No duplicate workspace link group in the rail (one landmark per purpose; `auth.spec.ts` asserts `link "API keys"` count 0 for a viewer anywhere on the dashboard, which a permission-filtered rail group would also satisfy, but the sub-nav alone is simpler).
- **D8 The inspector keeps `EventDrawer`'s DOM; no inspector tabs; no `data-wide`.** Scroll-to-section "tabs" would be `role="tab"` without tab panels (fake ARIA); the sections get condensed labels instead. The column is `--insp-w: 26rem`, user-resizable with CSS `resize: horizontal` (min 20rem, max 60vw); diff and shell panels already wrap. Follow-up: real panels.
- **D9 Container queries replace the two viewport-based row rules.** `.pane { container-type: inline-size }`; `.tl-row` compact columns and `.waterfall` narrow widths move from `@media (max-width: 52rem)` to `@container (max-width: 52rem)` so the rows adapt to the pane's width (the pane is narrow whenever the inspector is open), not the viewport's. Chrome 105+, Firefox 110+, Safari 16+; Playwright runs system Chrome.
- **D10 No `position: sticky` run header and no sticky table headers.** `main.app-page` is a fixed-height flex column (`height: calc(100dvh - var(--top-h))`), so the run header stays put while the work area scrolls. Document pages (`main.page`) scroll the document with a sticky rail and top bar. Sticky `th` cannot work inside `.table-wrap { overflow-x: auto }` without breaking the 375 px rule, so it is dropped. **Stacked mode** (`@media (max-width: 52rem), (max-height: 36rem)`): the run page becomes a scrolling document again (header static, context column stacked above the pane, timeline/waterfall capped at `min(68vh, 44rem)`, inspector a fixed overlay under the top bar).
- **D11 The top bar's crumb/search container is `.topbar-crumbs`, never `.cmd`** (`.cmd` is `pre.cmd` for shell commands in `CodingSections` and `globals.css` 602-613).
- **D12 Pressed toolbar buttons use `background: var(--sel); border-color: var(--accent); color: var(--fg)`**, not `var(--accent)` + `#fff` (white on advisory cyan is 1.8:1 in dark mode; axe would fail `analytics.spec.ts`).
- **D13 `LiveIndicator` shows "● REC" with the text "Recording" when at least one run is RUNNING, else "○ Idle"**; it uses `useRuns({ project, statuses: ["RUNNING"] }, 1)` (already polled at `POLL_MS * 5`); no count (cursor pagination has no total). `role="status" aria-live="off"`. It renders nothing when `useWorkspaceOptional()` is null.
- **D14 Motion transitions only `transform`, `opacity`, `background-color`, `box-shadow`**; durations are tokens zeroed under `prefers-reduced-motion: reduce`; nothing animates on first paint.
- **D15 Accepted: `fullPage` screenshots of the run page become viewport-sized** (the document no longer scrolls there). Document pages are unaffected. Noted in the screenshots README.
- **D16 Contrast is a vitest test, not a scratch script**: `tests/tokens.test.ts` parses the `:root` blocks of `globals.css` (both schemes) and asserts every text role on its background (and on `--sel`, and each tone on its tint) is >= 4.5:1.

## Proposed design

### Frame (step 2)

```text
.shell  grid: var(--rail-w) minmax(0,1fr) / var(--top-h) minmax(0,1fr); min-height: 100dvh
  a.skip
  aside.rail (grid-row 1/3; position: sticky; top: 0; height: 100dvh; overflow: visible)
    Link.brand (span.mark + "Agent Black Box")
    div.scope: WorkspaceSwitcher (its <ul> becomes in-flow, not absolute), ProjectSwitcher (details of links; "All projects" + ws.projects)
    nav.nav[aria-label="Primary"]: Overview, Runs, Analytics, Experiments, Settings(session)
    div.rail-foot.who (session): email, SignOutButton
  header.topbar (sticky; top 0): Crumbs (from pathname: "Runs / <run name>"), LiveIndicator
  main#main[tabindex=-1].page | .app-page
```

`main.page { padding: 1rem 1.25rem }` for Overview, Analytics, settings, compare, experiments. `main.app-page { display: flex; flex-direction: column; height: calc(100dvh - var(--top-h)); overflow: hidden }` for the run page only (the runs list is a `.page`: a long table scrolls the document). Pages outside the shell (`/`, `/login`, `/invite`, workspace-unavailable) keep `main { max-width: 56rem; margin: 0 auto }` as a centred auth card with the brand mark.

Mobile (`max-width: 52rem`): one column; the rail becomes a horizontal strip under the top bar (`overflow-x: auto` inside the strip, brand + nav + scope + who), `.topbar` and `main` span the column.

### Run page (steps 4-7)

```text
div.run-detail.app-page
  header.run-head
    div.run-title: h1, StatusBadge, tag "n retries" (when > 0), span.id.muted (short id · agent · models · ordered by · started)

    dl.stats[aria-label="Run summary"]: Duration, Cost, Tokens, Model calls, Tool calls, Retries(warn when > 0), Errors(bad when > 0), Agents (multi-agent only), Files changed

    section.pane[aria-labelledby=tl-h]: h2#tl-h (sr-only text "Timeline"/"Waterfall"/"Evidence"), timeline toolbar (classes, errors only, groups), event-notice, p[data-testid=progress], Timeline | Waterfall | EvidenceList
    EventDrawer (unchanged DOM; new .drawer pane styles)
```

Column widths: `grid-template-columns: var(--ctx-w) minmax(0,1fr)` closed, `var(--ctx-w) minmax(0,1fr) var(--insp-w)` open, with `--ctx-w: 18rem`, `--insp-w: 26rem`. Under `@media (max-width: 100rem)` the rule `.work[data-inspector="open"]:not([data-context="open"]) { --ctx-w: 2.25rem }` collapses the context to the strip; `.work[data-context="closed"] { --ctx-w: 2.25rem }` always. At 1440 with the inspector open: 224 + 36 + 416 = 676 → pane 764 px. At 1920 everything fits: 224 + 288 + 416 = 928 → pane 992 px.

`focusTimeline()` keeps querying `[role="listbox"], [role="treegrid"]`; in the Evidence view it falls back to the evidence table region (`role="region" tabIndex=0`).

### Evidence view (step 7)

Derived from the loaded `events` only (no new endpoint): every event with `diff.artifact`, `shell.stdout_artifact` or `shell.stderr_artifact` (helpers in `lib/coding.ts`: `artifactId`; text via `lib/withheld.ts`: `contentText`, so a viewer sees the withheld wording and never the API's `[withheld]` placeholder). A table (`caption` "Evidence", columns: Kind (diff / stdout / stderr), Source (event type + offset, mono), What (file path / command / branch, or the withheld wording), Size (bytes when known), Open) inside a focusable `role="region"` labelled "Evidence". "Open" calls `jumpTo(event_id)` (selects the event and opens the inspector; the drawer's existing `ArtifactText` loads the content on request). Empty state: "No artifacts were captured in this run." `progress` reads "N artifacts in M events". Counts are bounded by the already-bounded event list.

### Runs list (step 8)

```text
div.runs (page)
  div.page-head: h1 "Runs" · p.muted count line ("N runs loaded…", moved up from the table foot; same text and aria-live)

  QueryChips · UnindexedNotice · SearchProblemNotice (tone panels)
```

No column layout for facets (they render only for a search that returned facets; a column that is usually empty is not a layout). Every role, name, test id and the DOM order of `RunsList.tsx` stay; only classes and wrappers change.

## Risks
