- Gap notes (`pacing.ts:25-52`, `73-82`) use the event-type family only. The announcement (`useReplay.ts:125-130`) uses `describe()`. `aria-valuetext` is "event i of n, duration". The scrub bar's first-error tick and its sr-only "First error at event N" reveal the error's position in advance, which is D2 by design ("the scrub bar shows ... the fault line marked"). `faultStep` is passed to Timeline/Waterfall ungated but is only rendered inside the fault line, which is gated by `reachedFault` (`RunDetail.tsx:819-826`, `842-846`).

The `/icon.svg` exclusion is by exact pathname, so the only request it could hide is a same-origin GET of the static icon, which cannot carry tenant data; the control test proves the browser issues it on any URL change. The API-backed viewer spec allows at most one request and only on the per-event route.

## P1 (must fix before merge)

### P1-1 A viewer's "Files changed" collapses every withheld path to one file

- `apps/web/src/lib/replay/project.ts:256-263`.
- The API serves a withheld `file.path` as the string `"[withheld]"` (`apps/api/src/abb_api/content.py:11`, mirrored by `fixtures/withhold.ts:29-41`), never as a non-string. `typeof path === "string"` is therefore true for every withheld event, every path is added as the same key, and `filesChanged` is 1 for any number of files; the `filesApproximate` branch (`\u0000<id>` sentinel) is dead code, and `filesApproximate` is rendered nowhere (`grep` over `src/components`: no use).
- Proven: a probe over the failed fixture plus three `file.modified` events on two distinct paths, passed through `withholdEvent`, gives owner 2, viewer 1, `filesApproximate` false. The committed tests do not catch it because the only viewer fixture (`baselineCodingRun`) modifies one file (`summary.files_modified` = 1), and neither viewer spec compares the "Files changed" figure with the viewer's own live header.
- Failure scenario: a viewer replays a run that touched 4 files; the live header says "Files changed 4", replay says 1 at every playhead including the last, which breaks acceptance 1 ("at the last event it equals the run summary") for the viewer role and contradicts ADR-120 ("roles are unchanged").
- Fix: detect withholding from metadata, `e.withheld_attributes?.includes("file.path")` (or equality with the API marker, but the metadata list is the contract), count such events individually and set `filesApproximate`; render the figure as approximate when the flag is set (for example "≈ N" with a title, or the live summary's `files_modified` once the last event is reached). Add a unit test with at least two distinct withheld paths, and make `tests/replay-run.test.tsx` "replay as a viewer" compare "Files changed" at the last event with the figure shown before entering replay.

### P1-2 "Cost so far" is the caller's estimate only; on server-priced runs it is $0 while the header shows the real total

- `apps/web/src/lib/replay/project.ts:264-270`; claims in `docs/decisions/ADR-120-visual-replay-level-1.md` ("Figures use the same rules as the run summary ... the API worker in production"; "At the last event the state equals the run summary") and plan criterion 1.
- The summary's `estimated_cost_usd` is the `CostEngine`'s effective total with precedence provider-reported > price book > caller's estimate (`apps/api/src/abb_api/cost/engine.py:117-124`, ADR-040). Events served by the API carry only what the client sent: `cost.estimated_usd` (the SDK's `cost_usd=`) and `cost.provider_usd` (`provider_cost_usd=`); no per-event priced amount is in `EventOut` (`runs/schemas.py` has no per-event cost). The projection reads `cost.estimated_usd` alone: `cost.provider_usd` is ignored even when present, and a run priced by the price book (the plain SDK path with tokens and a model name, no `cost_usd=`) sums to 0.
- Proven: the failed fixture with `cost.estimated_usd` stripped from every event projects to `costUsd` 0 with `unpricedCalls` 7 while the summary says the fixture's total. `unpricedCalls` is computed but never rendered (`grep` over `src/components` and `runHeadline.ts`'s `replayHeadline`: no use), so the page says "$0.00 so far" with no qualifier.
- Failure scenario: an engineer replays a production run traced by the Python SDK without `cost_usd=`; the live header says "$0.42"; replay's Cost figure and the headline detail say "$0.00 so far" at every playhead and "$0.00" at the last event. The parity property test cannot see it because the fixture builder sums the attribute (`fixtures/builder.ts:185`), and the API-backed spec compares no figures.
- Fix (smallest honest one for this phase): read `cost.provider_usd` before `cost.estimated_usd` (the engine's own precedence); when `unpricedCalls > 0`, render the figure as a floor ("≥ $0.00, 7 calls unpriced" in the Metric title and in the headline's detail, like `afterText` already does for the first-error cost); record in ADR-120 and `docs/KNOWN_ISSUES.md` (S2) that server-priced runs replay a floor until the API exposes per-event priced cost (a new field: not this phase). Add a unit test over events with `cost.provider_usd` only and with no cost at all, and an API-backed assertion that at the last event the replay Cost equals the live header's Cost or is marked as a floor.

## P2 (should fix)

### P2-1 The incremental live-append path (`setEvents`) is dead; every arrival rebuilds four structures

- `apps/web/src/lib/replay/useReplay.ts:210-218`; `project.ts:226-245`.
- `useReplay` constructs `new ReplayProjection(events, ...)`, `new ReplayPacer(events)`, `groupStops(events)` and `idIndex` in `useMemo`s keyed on `events` identity. `useLiveEvents` returns a new array on every live arrival (`live.ts:117-120`), so each arrival discards the projection and its checkpoints and re-walks from 0 to the playhead; `setEvents` (the prefix check, O(n), and the "keep the accumulators" logic) is called only from tests. ADR-120 says the projection "is incremental" and the plan's risk note promises live events "append". It still works (the hook test "a live run: events that only append" passes because the rebuild is correct), but it is O(4n + index) per arrival rather than O(1), and the docs describe code that does not run.
- Fix: hold the projection in a ref and call `projection.setEvents(events, ctx)` when `events` changes (and rebuild the pacer/stops only when `extends_` is false), or delete `setEvents`/`lastApplied` and reword ADR-120 and the project.ts header. Either way, one test that asserts a live append does not re-apply the prefix through the hook.

### P2-2 With the inspector open on a later event, playback hides it but keeps `inspectorOpen`, so Esc goes dead

- `apps/web/src/components/RunDetail.tsx:338-351` (`drawerId` null while `drawerEventId` is set), `:166-171` (`inspectorOpen: drawerEventId !== null || leaving !== null`), `useReplay.ts:438-441`.
- Scenario: the inspector is open on event 12; the person seeks to 0 and presses play. While the playhead is below 12, `drawerId` is null, no dialog renders, but `inspectorOpen` is true: Esc on the page body does nothing at all (the hook returns before `leave()`), and Esc on the timeline needs two presses (`onEscape` → `replay.escape()` false → `closeDrawer()` of nothing). The follow (`setDrawerEventId(currentId)`) only runs while paused, so the dead state lasts as long as playback.
- Fix: derive `inspectorOpen` from what is rendered (`!!inspected`), or clear `drawerEventId` when `drawerId` is nulled by the playhead. Add a hook/run test: inspector open on a later event, play, Esc leaves replay in one press.

## Areas with no substantive issues

- Projection correctness (`project.ts`): checkpoint restore has no off-by-one (keys are applied-counts at multiples of `every`; restore clones and continues from `acc.applied`; verified by the backward-jump test at 4095/4096/4097 and by reading `advance`). The finished-span log is index-ordered and never truncated, so `log.slice(0, finishedLen)` is exact after any jump. Duplicate opens are ignored and a close without an open is dropped (no throw). NaN/missing timestamps give zero gaps and leave `maxOffset` alone; elapsed is a running maximum. Null sequences do not matter (the playhead is an index into `sortEvents` order). First error as event 0 or as the last event: `firstErrorReached` is `index >= firstErr`, the pause check only fires on a tick to `next === firstErr`, which is correct for both.
- Playback: one chained `setTimeout` per tick, cleared on every dependency change, so a quick speed change or StrictMode double-effect cannot double-fire; the end stops itself; play-from-end restarts; the hidden tab pauses; unmount clears the URL timer (tests assert `getTimerCount()` 0). Live status change rebuilds the projection through `status`/`firstErrorId` deps, so a run that finishes mid-replay gets its first error and pause.
- Keyboard: document listener runs after React's root handlers, and both Timeline and Waterfall `preventDefault()` for every key they handle (`Timeline.tsx:189`, `Waterfall.tsx:293`), so Space/Esc/`[`/`]` never double-fire; Esc order (menu, inspector, replay) is right; typing targets and modifiers are excluded; `r` conflicts with nothing (no other `r` binding in `src`). The 375 px menu handles Esc with `stopPropagation` and returns focus; outside click closes it.
- CSS: both new files use tokens only; `motion-contract.test.ts` and `tokens-use.test.ts` read every `src/app/*.css` so they cover `replay.css` and `run-replay.css` (VERIFIED, both pass); no animation or transition is declared; red is only the `.replay-fault` tick (allowlisted); the fault draw-in stays gated in `run-motion.css`.
- URL: Next 16.3.8 syncs `useSearchParams` with native `replaceState` (the pre-existing `?view=` code relies on the same); `changeView` now reads `location.search` so `t` survives a view switch; writes go to the current pathname only.
- Tests: expected values in `e2e/replay.ts:50-64`, `tests/replay-run.test.tsx:55-75` and `tests/replay-projection.test.ts:14-51` are reduced from the raw events without the module under test. Timing bounds are generous (150/500 ms, 700 ms frame gap) and the replay specs wait on rendered state. The only fixed sleep is the icon control test's 1.5 s, which is a control, not an assertion of replay.
- Scope: no new endpoint, no schema change, no server state, no export, no dependency change; the `scripts/auth-e2e.sh` edit is the one-line spec addition the plan called for.
