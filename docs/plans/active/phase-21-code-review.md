## Findings

### R1 (P1, CONFIRMED, regression) Hydration mismatch on every run page: `Crumbs` fires the run query before the page hydrates

- Where: `apps/web/src/components/shell/Crumbs.tsx:18-21` (`RunName` calls `useRun(runId)`), rendered from
  `AppShell.tsx:72` in the workspace layout, outside the page's `<Suspense>` in
  `apps/web/src/app/w/[workspace]/projects/[project]/runs/[runId]/page.tsx:15`.
- Repro: `cd apps/web && pnpm exec playwright test e2e/fixtures.spec.ts -g "security headers" --repeat-each 6` → 3/6
  fail with React #418. Unminified (next dev on :3191, 6 parallel loads of RUN 2): 4/6 pages log
  `Hydration failed because the server rendered HTML didn't match the client` with the diff
  `<div className="state" role="status" aria-live="polite">` (server: `Loading`) vs
  `<div className="run-detail app-page">` (client). The same 6-worker run against `origin/main` on :3192: 6/6 clean.
  Sequential loads (18 routes × 3) on an idle server: clean; the window opens only when hydration of the page
  boundary is slower than the fixture round-trip, which is why it looks like a load flake.
- Mechanism: the layout (rail, top bar) hydrates first; `RunName` starts `useRun(runId)`; the fixture/API reply lands
  in the shared QueryClient before React hydrates the page's Suspense boundary; `RunDetail`'s hydration render then
  sees `run.data` and renders the full page where the server HTML has the spinner. React throws, discards the server
  HTML and re-renders the tree on the client (double render of a 10,000-event page, console error, and the locked
  "console must stay clean" test fails).
- Fix (smallest): make `RunName` read the cache without starting the query before hydration, e.g.
  `useRun(runId, { enabled: hydrated })` where `hydrated` comes from
  `useSyncExternalStore(() => () => {}, () => true, () => false)`; or render `RunDetail`'s initial state from the same
  hydration guard. Add `--repeat-each 6` of the security-headers test to the evidence. Also correct the plan's
  "Gates" note (step 5-8) that blames `document-title`/load: it is a deterministic race, not axe.

### R2 (P2, CONFIRMED) The Evidence view renders every artifact row: DOM is unbounded

- Where: `apps/web/src/components/EvidenceList.tsx:29-78` (plain `<table>` over `rows`), `lib/evidence.ts:45-70`
  (one row per `diff.artifact`, `shell.stdout_artifact`, `shell.stderr_artifact`), `RunDetail.tsx:326`.
- Repro (my `a4-perf.spec.ts`, RUN 6 with a `diff.artifact` on every `file.read`): `?view=evidence` renders
  **3,556 `<tr>` and 35,791 DOM elements** in 625 ms; a run with stdout+stderr on every shell event would be 3× the
  event count (30,000 rows on a 10,000-event run). Timeline (29 options) and waterfall (28 rows) stay bounded; the
  plan's claim "counts are bounded by the already-bounded event list" is wrong because `useRunEvents` pages the whole
  run in (`queries.ts:104-114`, 500 per page, no cap).
- Fix: reuse `@tanstack/react-virtual` as the timeline does (fixed 32 px rows), or cap the table at N rows with a
  "Show more" control and keep the count in `progress`. Add a `design.spec` bound like the ones for the other views.

### R3 (P2, CONFIRMED) The fixture viewer workspace withholds nothing from events, so the viewer tests in `design.spec.ts` prove nothing and AC11's claim is false

- Where: `apps/web/src/fixtures/api.ts:58-160` passes `viewer` only to `fixtureWorkspaceReply`, `fixtureRunEvaluations`
  and `fixtureComparison`; events, spans and search never see it. Browser check on
  `/w/viewer-only/projects/all/runs/RUN 7` with the first error open: `WITHHELD_TEXT` present: **false**,
  `payload-withheld` count: **0**; the inspector shows the real attributes. So `design.spec.ts:395-403` and `:440-448`
  ("a viewer sees the withheld wording", "a viewer's evidence view never shows the placeholder") only assert that a
  string the fixture never emits is absent. The closing-evidence row for AC11 says the design spec checks that the body
  "contains `WITHHELD_TEXT`"; no such assertion exists.
- What is still true: with withheld events injected at the proxy (every content attribute replaced by `[withheld]` and
  listed in `withheld_attributes`, payload withheld, span names withheld), timeline, waterfall, evidence, inspector
  (Attributes/Identifiers/Payload), story, agent tree and folded strip show only "content withheld for your role";
  `[withheld]` and the original strings appear nowhere in `outerHTML`, any attribute (`title`, `aria-label`, `data-*`)
  or client state reachable through the DOM (my `a2-withheld.spec.ts`, screenshot `withheld-evidence.png`). The real
  path is covered by the locked `multiagent.spec` and `auth.spec` viewer tests, which pass. Rating P2 for the honesty of
  the evidence, not for a leak.
- Fix: either teach the fixture data source to withhold events for `viewer-only` (`fixtureReply` → a `withholdEvents`
  projection mirroring `apps/api/src/abb_api/runs/content.py`), or have the three design-spec tests inject withheld
  responses via `page.route` as `e2e/artifacts.ts` already does, and assert `WITHHELD_TEXT` is present. Correct AC11.

### R4 (P2, CONFIRMED) Expanding the folded context strip drops keyboard focus to `<body>`

- Repro: 1440×900, RUN 2, open the inspector (`e`), Tab to "Show run context", press Enter: `aria-pressed` on the
