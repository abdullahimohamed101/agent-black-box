## Outcome

A stranger can find the project, understand it in one page, run it in minutes with no API key, see the same meaningful traces every time, and trust what the README says because every claim is checked by a script or marked as unverified. Concretely: a public-launch-ready repository (Apache-2.0, contributing and security policy, templates), a static landing page that builds on the design tokens and the self-hosted fonts and makes no third-party request, a README with real screenshots, the three examples and `make demo` running a deterministic scripted agent by default, a live-run health that no longer says "no data" for the whole life of a run (KI-097), docs for quickstart, deployment (self-host), troubleshooting and the existing reference docs brought up to date, and a scripted release checklist wired into `scripts/quality.sh`. The short demo recording is a later, gated step.

## Non-goals

- The hosting guide and recipe (private hosting: reverse proxy with automatic HTTPS, domain, volume, real OIDC): a separate later plan (KI-188). This plan's deployment doc covers only "run the compose stack yourself" and links the existing runbooks.
- Pushing, opening the PR, enabling GitHub Pages, making the repository public, tagging a release, publishing packages to PyPI/npm: all need the user's explicit approval (AGENTS.md "Git Safety"); the plan prepares them and stops.
- The demo video recording (gated final step G1; WebM needs nothing new, MP4 needs `brew install ffmpeg` and the user's approval).
- A designed brand mark (D5 keeps the placeholder pulse glyph).
- New product features: no new pages, no new event types, no schema or tenancy changes. The only behaviour changes are the KI-097 read path and cadence and two small accessibility/housekeeping fixes (KI-129, KI-123).
- A JavaScript framework or build chain for the landing page, analytics, cookie banner, or any third-party embed.
- Alert-history filters and the "an alert was sent" notes (KI-168): deferred (see Known issues).
- Redis/Kafka/ClickHouse/Kubernetes: no trigger; out of scope.

## Decisions

D1-D6 are the user's decisions, recorded verbatim in substance with rationale. D7 onwards are recommendations ("confirm before implementation" unless stated).

- **D1 (user) Release target: a public open-source launch.** Landing page, README with screenshots, license and contributing guide, self-host docs. Rationale: it is the audience the product was built toward, and it raises the bar on honesty (every claim checkable), documentation, and licensing; nothing is hosted, so there is no SaaS promise to keep.
- **D2 (user) Landing page: a standalone static site in `site/`.** Plain HTML and CSS, no JavaScript (amended by D18: React islands allowed), built on `apps/web/design-tokens/tokens.json` and the self-hosted IBM Plex fonts, no third-party requests, publishable to GitHub Pages. The product's `/` stays the login page. Rationale: the app is a dashboard behind sign-in and must not double as marketing; a static site is the cheapest thing that cannot leak data or break, and it matches the product's "no third-party request" stance.
- **D3 (user) KI-097 fix: throttle `detect_findings` while a run is active and show the last completed result with its age.** At most one analysis per ~10 s per active run, as a trailing job so the final state is always computed when the run ends; the health dimensions show the most recent completed result labelled with its age ("as of 12 s ago") instead of "no data". Needs a deterministic e2e (bounded polls, no wall-clock assertions), INV-1 and INV-2 intact (derived state stays rebuildable; no event is touched), and an ADR if the enqueue semantics change. Rationale: a live run is when health matters most; showing an older result honestly labelled is more useful than "no data" and is cheaper than analysing on every batch.
- **D4 (user) Examples and `make demo` run a deterministic scripted agent by default.** Three examples (coding, simple custom, multi-agent), no API key, same traces/failures/findings every run, seeded demo data; an optional `--live` flag swaps in a real provider. Screenshots and the video must be regenerable by script. Rationale: a first run must never depend on a key, a network or a model's mood, and screenshots must be reproducible so they cannot drift from the product.
- **D5 (user) Brand mark: keep the placeholder pulse glyph as the launch mark.** Produce proper SVGs (favicon sizes, social card, README header); swapping the mark later means replacing one SVG. Rationale: a designed mark is not needed to launch; isolating it in one source file makes the later swap cheap.
- **D6 (user) License: Apache-2.0 for the whole repo.** Root `LICENSE`, a `NOTICE` if needed, per-package metadata in every `pyproject.toml`/`package.json` (SDK and integrations too). Also `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, a root `SECURITY.md` (reporting address `[NEEDS INPUT]`: the user must give a contact), issue and PR templates. Rationale: a patent grant and a permissive license suit an SDK that other people embed in their agents; one license for the whole repo avoids per-package confusion. The IBM Plex fonts stay under their own OFL (`apps/web/src/fonts/OFL.txt`), which `NOTICE` records.
- **D7 KI-097 mechanics (confirm before implementation).** Two parts. (a) *Read path:* when the findings state would be `processing` and `run_findings_state.computed_at` exists, health uses the stored findings and reports each finding-based dimension with a new `as_of` timestamp (the earlier `computed_at`) and a human label; `status` keeps its current vocabulary (`none|processing|current|outdated|failed`) so existing clients are unaffected, and a run never analysed still reads `no_data` ("not analysed yet"). `outdated` (detector rules changed) and `failed` keep `no_data`, since a result from older rules or a failed analysis is not honest to show as current. (b) *Cadence:* a per-run minimum interval, default 10 s (`ABB_FINDINGS_MIN_INTERVAL_SECONDS`), enforced where the job is enqueued: the delay is `max(detect_delay(...), min_interval - age(computed_at))` measured on the database clock; the job stays one coalesced pending job per run (`dedupe_key`), so events arriving meanwhile coalesce into it, which makes it trailing by construction. When the summary shows the run has just become terminal, the job is enqueued with no throttle delay so the final analysis is computed promptly. The builder first characterises the current behaviour with a failing test (the existing 5 s coalescing delay already limits the rate; the defect is the read path and the missing minimum interval), and only if the enqueue semantics change does ADR-174 record it (it will: terminal bypass and the interval floor). Rationale: smallest change that meets D3 while reusing the coalescing outbox.
- **D8 `as_of` contract (confirm before implementation).** Add an optional `as_of` (timestamp) and `stale` (boolean) to the health dimension objects that depend on findings, and the UI renders "as of 12 s ago" from `as_of` against the response's server time (the label recomputes on the client's tick; the test injects the clock). This is an additive OpenAPI change: regenerate `apps/api/openapi.json` and the web client (`pnpm --filter @abb/web gen:api`), no breaking change. ADR-081 gets a dated amendment note via ADR-174.
- **D9 Demo determinism definition.** "Same every run" means the same agents, spans, tool and model calls, errors, retries, findings (types, severities, evidence shape), costs and statuses; ids and wall-clock timestamps differ. `scripts/demo-e2e.sh` runs the demo twice on a throwaway database and compares a normalised summary (ids and timestamps removed); a difference fails. The scripted agents use fixed sequences and a fixed fake model price table, no randomness, no network. The "simple custom" example becomes a small scripted agent with one deliberate failure and a retry (the current four-line sample is kept as the SDK snippet in the README).
- **D10 `--live` scope.** `--live` exists on the coding example (it maps to the existing `--model anthropic`, keeping the required `--i-understand-this-runs-commands` warning) and on the simple custom example (a plain Anthropic or OpenAI call through the existing integrations, no tools that execute commands). The multi-agent example stays scripted-only and says so (its value is the trace shape, not the model). `--live` is documented as "not run by the project in CI"; it is exercised only if the user supplies a key and approves (KI-044). `make demo` never passes `--live`.
- **D11 Screenshots come from the real stack with demo data, not fixtures.** `make demo` followed by `scripts/screenshots.sh` (Playwright, 1440x900 and 375 widths, light and dark where the README uses both) writes to `docs/screenshots/release/` and nowhere else; it reads `SHOTS_DIR`-style gating so ordinary e2e runs cannot rewrite it (KI-123). Reason: the project's founding promise is that the UI shows what the agent did, so the pictures come from a real run through the real pipeline. Size budget: at most 12 PNGs, each under 400 KB, checked by the release checklist; the README links committed images (no external image host).
- **D12 Landing page build** (amended by D18: the shipped site is a Next static export, not `build.mjs`). `site/` contains `index.html`, one `styles.css` produced by `site/build.mjs` (a small Node script, run in CI and by `make site`) from `tokens.json` (same variable names as the app), the four woff2 files copied from `apps/web/src/fonts/` with `OFL.txt`, the SVG assets, and relative links only so it works under a GitHub Pages project path (`/agent-black-box/`) and at a custom domain root. `scripts/check-site.sh` fails on any `<script>`, inline event handler, `@import`, `url(` pointing off-site, external `src`, `href` on `link`, or `<iframe>`; it also checks size (budget 250 KB excluding fonts), contrast through the existing tokens contrast table, and takes screenshots at 375 and 1440 widths in light and dark. A Pages deploy workflow (`.github/workflows/pages.yml`, actions pinned by sha, passes `check-pins`) is added but does nothing until the user enables Pages; enabling Pages and any custom domain are the user's actions.
- **D13 Release checklist is a script, not a document.** `scripts/release-checklist.sh` runs: placeholder-text scan over shipped surfaces (`site/`, `README.md`, `apps/web/src`, `docs/*.md` except plans/design/research; allow-list file for deliberate occurrences), `[NEEDS INPUT]` outside plans/design/research, debug-logging scan (`console.log`/`debugger` in `apps/web/src`, `print(`/`breakpoint()` in `apps/api/src`, `packages/sdk-python/src` and integrations except CLIs on an allow-list), secrets scan (tracked `.env*` other than `.env.example`, high-entropy and known-prefix patterns, over the working tree and `git ls-files`), license metadata present and equal to `Apache-2.0` in every package, relative-link check across `README.md`, `docs/`, `site/`, `CONTRIBUTING.md`, a broken-route crawl (every rail/top-bar link and every link in the setup guide returns 200 and no page contains "undefined", "NaN", "[object" or "TODO" text, against the fixtures build and the demo-seeded stack), a no-third-party-request assertion (Playwright records every request while crawling the app and the site; any host other than the page's own fails), and the screenshot budget. "Fake charts" is scripted as: every chart/figure component on the crawled pages has a non-empty data source in the demo-seeded stack and no chart renders from a literal in `apps/web/src` (grep for hard-coded series in chart components, allow-list for test fixtures). Items that cannot be scripted (visual taste, copy tone) are listed in the plan's manual checklist and reported as ASSUMED, never PASS. The script is wired into `scripts/quality.sh full` for the static parts and into its own CI job for the crawl parts.
- **D14 Documents are plain Markdown with a link checker.** New docs: `docs/README.md` (index), `docs/quickstart.md`, `docs/deployment.md` (self-host), `docs/troubleshooting.md`; existing reference docs (`architecture/{events,api-v1,sdk-python,integrations}.md`, `SECURITY.md`, `OPERATIONS.md`, `development/setup.md`) are checked against the current code and updated, not rewritten. Command blocks in the quickstart and deployment docs are executed by a script (`scripts/docs-commands-check.sh` runs the quickstart's commands on a throwaway database) so the docs cannot rot silently. No hard-coded test counts or phase tables in the README (they go stale); the README links the roadmap instead.
- **D15 (user) Name casing is "Agent BlackBox"** (one word "BlackBox") in prose, decided 2026-10-18. Repo and package slugs stay lowercase (`agent-black-box`; the import name became `agent_blackbox`, ADR-177). Files written from now on use the new casing. A repo-wide rename (README, UI wordmark and page titles, docs; ADR text excluded) is a later step still to be scheduled; until then the old casing "Agent Black Box" remains in about 179 lines: apps/web 11 files, apps/api 10, docs/design 7, packages/event-schema 5, examples 8, integrations 15, deploy/observability 4, docs/plans 4, docs (runbooks, research, decisions, architecture) 4, packages/sdk-python 2.
- **D16 (user) No custom domain.** The landing page ships on the default GitHub Pages URL (a project page under the repository owner). `site/` must therefore work under a sub-path base: use only relative URLs and check this in `scripts/check-site.sh`.
- **D17 (user) The demo video has no music**: silent, captions only. No music licence is needed.
- **D18 (owner) The no-JavaScript constraint of D2 and D12 is lifted** (decided 2026-10-19, mid-design; `docs/design/launch/landing-site-brief.md` line 17). React is allowed on the landing page; the static export, the self-hosted fonts and zero third-party requests stay, and every section still renders its full state without JavaScript. D2 and D12 above are amended accordingly: read "Plain HTML and CSS, no JavaScript" as "a Next static export with a few islands". The plan's `nojs` check (`scripts/check-site.sh nojs`) keeps the page readable with scripts disabled.

Decisions that need an ADR: **ADR-174** (KI-097: live health reads the last completed analysis; minimum analysis interval; terminal bypass; amends ADR-081 and ADR-080's cadence), written in step 3. D6 (license) is recorded in the plan and the repo; a one-paragraph ADR-175 "Apache-2.0 for the whole repository, fonts under OFL" is written in step 1 because a future contributor could reasonably question it.

## Risks

- **A license is a legal choice.** Apache-2.0 was chosen by the user; the copyright holder name/year in `NOTICE` and the CoC/security contacts are `[NEEDS INPUT]`; do not guess them. Mitigation: placeholders fail the checklist in `--release` mode, so they cannot ship by accident.
- **Deterministic e2e flakiness (KI-097).** The 19a/19b/19c reviews found e2e checks racing counters and clocks. Mitigation: bounded polls only, the minimum interval set large in the test so no wall-clock timing is asserted, database-clock-injected unit tests for the arithmetic, and a repeat-run check (the stage run three times in a row before commit).
- **Behaviour change in enqueue semantics** could starve a run's final analysis. Mitigation: terminal bypass, a test that a long-running run still gets a final analysis, `0` disables the floor, kill switch documented.
- **Screenshots and fonts bloat the repo.** Budget of 12 images under 400 KB and an enforced check; fonts reused, not duplicated beyond the site's copy (a size line in the checklist).
- **Secrets scan false positives/negatives.** Patterns plus allow-list reviewed in step 17; the scan never prints a matched value (prints file and line only), so the checklist itself cannot leak a secret into CI logs.
- **Claims drift.** The README is mostly links and commands that are executed by a script; counts are omitted by design.
- **Pages workflow publishes content.** Added disabled-by-default (the repository setting is off until the user enables it); pinned by sha; limited to `site/`; permissions minimal (`pages: write`, `id-token: write`, `contents: read`).
- **`make demo` reset deletes data.** `demo-reset` is limited to the demo project by slug, dry-run by default, and refuses any other project (tested).
- **Locked specs.** Several steps edit specs the earlier phases locked; edits are limited to the renamed control and screenshot gating, listed in the commit message, and no assertion is removed or weakened.
